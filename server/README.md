# Справочный сервис ETWallet

Node.js · Fastify · TypeScript

Отдельный пакет. Расширение работает и без него: сервис — источник
обновлений справочных данных, а не условие работоспособности кошелька.

## Чего этот сервис не делает

Это главное свойство, и оно обеспечено устройством кода, а не обещанием.

| Запрет | Чем обеспечен |
| --- | --- |
| Не получает seed-фразы и приватные ключи | Ни один маршрут не принимает произвольный JSON: схемы строгие, лишнее поле отвергается. Плюс охранник на входе отвергает тело, похожее на ключ или мнемоническую фразу, до разбора и до журналирования |
| Не подписывает транзакции | В зависимостях нет ни одной библиотеки эллиптической кривой, BIP-32 или BIP-39. Подписать нечем. Тест `no-signing-dependencies.test.ts` падает при появлении такой библиотеки в `package.json` либо в импортах |
| Не связывает пользователя с адресами | Ни один читающий маршрут не принимает адрес кошелька — ни в пути, ни в строке запроса. Каталоги одинаковы для всех |
| Не читает настройки пользователя | Хранится непрозрачный шифротекст. Кода расшифровки в сервисе нет |
| Не уводит на посторонние адреса | Проверка каталога отвергает уведомление и пояснение к выпуску, содержащие что-либо похожее на ссылку. Ответ о версии не содержит адреса загрузки |

Честная оговорка: сервис не может проверить, **что именно** зашифровано
в присланном шифротексте. Гарантия «ключи сюда не попадают» держится
на том, что их туда не кладёт кошелёк, а не на способности сервиса
это различить. Поэтому в кошельке ключевой материал в синхронизацию
не попадает по построению, а не по договорённости.

## Запуск

```bash
npm --prefix server install
```

```bash
npm --prefix server run dev
```

Сборка и боевой запуск:

```bash
npm --prefix server run build
```

```bash
NODE_ENV=production ALLOWED_ORIGINS=chrome-extension://<идентификатор> npm --prefix server start
```

Проверка:

```bash
npm --prefix server run verify
```

Настройки читаются из окружения, образец — в `.env.example`.
В боевом режиме `ALLOWED_ORIGINS` обязателен: молчаливое «разрешить
всё» в проде хуже отказа, потому что отказ заметят при развёртывании.

## Маршруты

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/v1/health` | Проверка живости |
| GET | `/v1/networks` | Каталог сетей |
| GET | `/v1/networks/:chainId/rpc` | Рекомендуемые RPC-адреса сети |
| GET | `/v1/networks/:chainId/tokens` | Рекомендуемые токены сети |
| GET | `/v1/notifications` | Действующие системные уведомления |
| GET | `/v1/app/version` | Состояние версии, `?version=X.Y.Z` необязателен |
| GET | `/v1/settings/:syncId` | Зашифрованные настройки |
| PUT | `/v1/settings/:syncId` | Запись настроек |
| DELETE | `/v1/settings/:syncId` | Удаление настроек |
| POST | `/v1/users` | Строка в `public.users` (`username`, `balance`, `the_p`) |

`chainId` передаётся десятичной строкой и возвращается строкой:
по стандарту он не ограничен 53 битами, а `JSON.parse` молча теряет
точность. Идентификатор сети, отличающийся от настоящего, — это подпись
транзакции для другой цепи.

## Каталог хранится в репозитории, а не в базе данных

Каталог определяет, какие адреса контрактов кошелёк покажет как
рекомендованные, — то есть куда пользователь отправит деньги.
Изменение такого значения обязано проходить через ревью и историю
правок, а не через `UPDATE`, доступный любому, кто получил доступ
к серверу.

Каталог проверяется при запуске. Сервис с испорченным каталогом
не поднимается: отказ при старте видит тот, кто разворачивает сервис,
а ошибка в выдаче не видна никому, пока не станет поздно.

Что проверяется: контрольная сумма EIP-55 у каждого адреса токена,
`https` у каждого адреса, отсутствие повторов, наличие хотя бы одного
узла у каждой сети, отсутствие ссылок в текстах уведомлений,
непротиворечивость версий.

## Как токен попадает в каталог

Адрес обязан подтвердиться **двумя независимыми источниками**:

1. опубликованным списком токенов (сейчас — Uniswap Labs Default 22.6.0);
2. живым контрактом: `symbol()`, `name()` и `decimals()` запрашиваются
   у узла и сверяются со списком.

Расхождение источников — повод исключить запись, а не выбрать один
из вариантов. Так из каталога выпал USDT в сети Polygon
(`0xc2132D05D31c914a87C6611C10748AEb04B58e8F`): список называет его
`USDT` / «Tether USD», а контракт при сверке ответил `USDT0`.

Поле `provenance` отдаётся клиенту. Признак «проверено» непроверяем,
происхождение — проверяемо, и пользователь вправе видеть, на чём
основана рекомендация.

Сети BNB Chain и Avalanche записей не имеют: они не покрыты
использованным списком, а сверять по одному источнику — значит
не сверять вовсе. Пустой список для известной сети означает
«подтверждённых рекомендаций нет», а не «токенов не существует»,
и неизвестная сеть отвечает `404`, а не пустым списком.

## Синхронизация настроек

Идентификатор синхронизации — 32 случайных байта, порождённых
на устройстве. Он **не выводится** ни из seed-фразы, ни из адреса:
связь «идентификатор — адрес» превратила бы справочный сервис в реестр
«личность — портфель».

Идентификатор — ключ-предъявитель: кто его знает, тот может прочитать
шифротекст (бесполезный без ключа шифрования) и перезаписать его.

Запись требует номера текущей версии. Несовпадение — отказ `409`:
два устройства, писавшие одновременно, иначе затёрли бы изменения
друг друга молча.

Хранилище — в памяти процесса, и это осознанно: синхронизация
работает как зеркало, а не как источник истины. Настройки живут
на устройстве, сервис лишь помогает перенести их на второе. Постоянное
хранилище подставляется одной строкой — интерфейс `ISettingsRepository`
для этого и выделен.

## Устройство

```
src/
  api/          контракт и маршруты
  catalog/      данные каталога, проверка, доступ
  settings/     хранение зашифрованных настроек
  plugins/      защитная обвязка и охранник входящих данных
  lib/          адреса, версии, признаки секретов, ошибки
  app.ts        сборка приложения
  config.ts     настройки из окружения
  index.ts      точка входа
```

Тот же исходник Node исполняет напрямую (стирая типы) и собирает
в `dist`: импорты указывают расширение `.ts`, а компилятор переписывает
его в `.js`.
